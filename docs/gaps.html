What the register does not tell you

What this register does not record, and where it is easy to read wrongly.

A register is only as useful as it is readable. This page shows what the published register does not record, and where it is easy to count wrongly.

None of this is a claim that anyone did anything wrong. Every finding describes the file as published. Five rules apply to every figure on this site: how to read these numbers.

Where the numbers come from. Anything labelled published is a figure the source states in its own summary. Everything else was counted from the data file by this project. Where the two disagree, both are shown.

Five questions, with what the published register can answer. Select one to read the finding it comes from.

The register counts two different kinds of thing

Agencies report their AI two ways, and the two cannot be added together. The headline count includes only the first.

entries are reported individually, one per system.

The second route is consolidated reporting: rather than list every common tool, an agency ticks a shared list of ordinary tasks done with off-the-shelf software, meaning products bought ready-made. agencies report this way against tasks, giving combinations marked in use.

Never added together.

Completeness varies far less within an agency than across the list

Inside a single agency's submission, entries are filled in to almost the same degree as each other. Across the whole list, the range is wide. What produces that pattern is not visible in the file, which records nothing about who filled an entry in or when.

Each entry has core fields.

Put plainly: entries from the same agency are filled in to a similar degree as each other, and entries from different agencies are not. That is what was counted. Whether it would hold for a submission this project has not seen was not tested.

The register cannot say how current any entry is

Nothing records when an entry was last checked, so a description written last month and one written years ago and never revisited look identical.

What would call for a re-check, and what the register would notice

Five kinds of change would normally mean an entry needs verifying again. The register records none of them as a change.

    Seven ways a careful person would still get these numbers wrong

    Suppose you downloaded this register and opened it in a spreadsheet to answer a simple question, such as how many entries say which groups of people the system affects. You would get a wrong answer, and nothing would tell you it was wrong.

    These seven are the reasons. They are properties of how the files are written, not of what any agency reported.

    Two fields look fully answered and are almost empty. Where a question lets you tick several boxes, ticking none is stored as two square brackets with nothing between them, like this: []. A spreadsheet counts those brackets as an answer.

    Press the button and watch what those two fields actually hold.
