Keeping a register current

A proposal for how a register would be kept up, written against the five things the field set does not do. Not tested against any real register.

What this page covers, and what it does not

Five mechanisms

One for each thing the field set does not do. Each carries the same five answers in the same order, so they can be read against each other: what it is, who does it, what sets it off, what it leaves behind, and what it costs.

How you would know it is working

Each of these is read from the register itself. None asks the people who keep it how it is going, because an answer from the people who keep a register is the thing this project exists to look past.

    What would show this to be wrong

    A design with no way of being wrong is not a design.

      Read this last

      The other four pages can be checked against a published file. This one cannot. It is one person's account of how a register would be kept current, written against five things the audit found missing, and it has not been used to keep anything.
